# 后端开发记录

## 2026-10-02：Java 17 后端与第一轮接口对接

### 技术基线

- Java 17、Spring Boot 3.5.16、Maven Wrapper 3.9.9。
- 本地服务端口 `12345`，生产接口前缀 `/api/v1`。
- 经典注解式 MVC 分层：Controller、Service、Store；数据访问使用 Spring JDBC。
- MySQL 5.7 为正式本地数据库，H2 MySQL 模式用于自动化测试。
- 密码等连接信息只由环境变量提供，仓库不保存本地凭据。

### 数据与标识

- 存档、文集、题目、知识点、课卷、作答记录的数据库主键均为 UUID。
- 内置旧题库的短 id 在首次入库时确定性转换为 UUID，重复初始化不会改变关联关系。
- `study_attempt` 保存发题时的题目与答案快照；题库后来修订也不会改变已经发出的课卷。
- `answer_record` 通过游戏、课卷和题目 UUID 保存作答结果，同一课卷只能结算一次。

### 低流量策略

- `/bootstrap` 只返回存档摘要、文集 UUID、修订号和数量，不返回题目正文。
- 浏览器按文集 revision 下载 `/question-banks/{uuid}`，把 Markdown、选项和解析缓存到 IndexedDB。
- revision 未变化时直接使用浏览器缓存；短时离线可继续使用旧缓存。
- 答题请求只传 `attemptId`、`questionId` 和答案。
- 游戏历史在服务端响应中只传 `questionId`，HTTP 适配器从本地文集缓存补回题面。
- JSON 响应超过 1KB 时启用 HTTP 压缩。

### 已接通接口

- 启动数据、文集清单与按 UUID 下载文集。
- 新建、读取、删除、导出、导入存档。
- 地图移动、人物话题、县试报名。
- 开始、答题、下一题、结算和中止活动。
- 普通活动按 5 个不同知识点组织；主线与科举按 10 个不同知识点组织。
- 首题答错后留在同一知识点抽取低难度训练题，答对才进入下一个知识点；训练题不补分。
- 物品购买/使用、札记批注、配置调整、章节确认和故人里程碑。

### 自动验证

- 后端集成测试覆盖建表、启动协议、UUID、内置题库导入、存档 CRUD、活动发题和 UUID 答题提交。
- 前端 Vitest 现有 14 项测试全部通过。
- TypeScript 与 Vite 生产构建通过。

### 后续顺序

2. 把游戏响应进一步改为按 revision 返回增量补丁，继续降低频繁行为请求的响应体积。

## 2026-10-02：府城、府试与旧存档扩容

- 地图契约增加 `regions` 与地点 `regionId`，前端按大地图切换底图，只渲染当前区域的小地点。
- 接入临川府五处地点、两名可交互人物、十一项活动、五件新物品和三段阶段事件。
- 科举面板由单场县试改为配置驱动的多考试标签；侧栏自动追踪第一场尚未取中的考试。
- 临川府试复用后端科举状态机，仍按十个不同知识点、十题全对取中、失败无惩罚、无限次重试执行。
- Java 读取旧存档时自动补齐新增人物和考试记录；既有好感、物品、答题记录和进度不被覆盖。
- 增加内容校验脚本，生产构建会检查跨文件 id、地图归属、活动引用、头像和背景文件、科举活动以及题目 1–3 个知识点约束。
- 新地图和头像均已接通最终路径，仓库内暂放开发占位图；正式生成提示词、尺寸与替换路径记录在 `docs/map-background-assets.md`。
- 命令行当前全局 `JAVA_HOME` 仍指向 JDK 11，验证时显式使用 `D:\Java\jdk-17.0.2`；IDEA 的项目 JDK 设置不影响已有 PowerShell 会话。

## 2026-10-02：受保护的题库管理写接口

- 新增单文集原子导入/修订接口和文集元数据修改接口，解决服务端模式下文集无法改名的问题。
- 管理写接口默认关闭；仅配置 `APP_ADMIN_KEY` 后启用，并使用 `X-Admin-Key` 请求头鉴权。密钥不进入普通游戏前端，也不写入仓库。
- 导入前校验文集、题目和知识点 UUID，1–3 个知识点引用，题型、选项、答案、难度与权重；校验失败不会改动数据库。
- 同一文集 UUID 重新导入只替换这一部文集并递增 revision。客户端会沿用 IndexedDB 缓存，只重新下载变动的文集。
- `docs/题库生成提示词.md` 已同步顶层 `enabled` 和 `weight` 字段，确保其他模型产物可直接交给管理导入接口。
