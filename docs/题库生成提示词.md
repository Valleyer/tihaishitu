# 《题海仕途》全服题库生成提示词

把下方“可复制提示词”全文、原始试卷/PDF/教材/讲义、答案解析，以及当前全服知识点清单一起交给其他 AI。对方最终只输出一个 UTF-8 JSON 文件，可由管理后台“批量导入”直接导入。

> 维护约定：本文件是全服题库导入格式的正式规范。代码调整导入字段或校验规则时，必须在同一次修改中同步更新本文、下方示例和 `frontend/public/examples/题库示例.json`，并运行后端导入集成测试。

## 可复制提示词

~~~text
你是一名专业题库工程师、学科教研员和数据标注员。请读取我提供的试卷 PDF、教材、讲义、答案与解析，并严格依据同时提供的“全服知识点清单”生成可直接导入《题海仕途》的全服题库 JSON。

你的最终回复只能包含一个合法 JSON 对象。不要使用 Markdown 代码围栏，不要附加解释、统计、道歉或 JSON 之外的文字。输出前必须自行完成格式、数学答案、公式转义、知识点引用和重复题检查。

一、系统约束

1. 系统以知识点为考核单位。普通副本抽取 5 个不同知识点，主线核心考核抽取 10 个不同知识点。
2. 每个知识点首题决定该知识点是否得分；首题答错后，系统继续抽取同知识点下更简单的诊断和训练题，直到掌握再进入下一个知识点。
3. 玩家可自由刷 0、1 或任意数量的题；不要设计每日题量、刷题目标、出身或玩家可选难度。
4. `difficulty` 只用于系统内部选择诊断题，范围为 1–5。
5. 知识点由服务器统一维护。导入文件不得创建或复制知识点，只能引用全服知识点清单里已有且状态为 active 的稳定 `code`。
6. 一道题关联 1–3 个细分知识点，至少一个关系为 `core`，其余可为 `auxiliary`。如果经常需要超过 3 个，应拆题。
7. 知识点应达到具体题型或独立能力粒度，例如“无条件极值的极值点判定”“参数方程的二阶导数计算”，不能只写“高等数学”“导数”等宽泛章节名。

二、原始题型、展示方式和判题方式

三者必须分别标记：

- `questionType`（原始题型）：`single_choice | multiple_choice | true_false | blank | solution`
- `presentationType`（游戏展示）：`single_choice | multiple_choice | true_false | self_assessment`
- `gradingMode`（判题方式）：`auto | self_assessment`

规则：

1. 单选、多选、判断题使用 `gradingMode=auto`，展示类型与客观题型一致。
2. 原始填空题和解答题保留原题，不要强行改成选择题；它们使用 `presentationType=self_assessment`、`gradingMode=self_assessment`。
3. 自评题不提供 `options`。玩家先独立作答，再展开参考答案、解析和知识点讲解，并选择“掌握 / 部分掌握 / 未掌握”。
4. 客观题的 `standardAnswer`：单选为选项键字符串，多选为选项键数组，判断为 JSON 布尔值。
5. 自评题的 `standardAnswer` 必须是 Markdown 字符串，并且足以核对关键步骤。
6. 保留原题真正考查的内容。可把过大的综合题拆成方法选择、关键中间量和结论等独立题，但不得歪曲原意。

三、题目质量

1. 每个知识点应有由易到难的同类题：至少包括 difficulty=1 的一步诊断题、difficulty=2 的直接应用题和 difficulty=3 的标准题；资料允许时补充 4–5 级变式。
2. 同知识点题目应考查同一核心能力，但改变数据、条件、叙述或陷阱，不能只机械换数字。
3. 错误选项应来自真实误区，如漏定义域、符号错误、混淆充分必要条件、漏验端点或遗漏协方差项。
4. 多选题至少两个正确项；判断题陈述必须具有唯一真值；禁止“以上都对/都不对”。
5. 逐题重新求解，保证答案与解析一致。原资料疑似错误时，只有能确定才修正，并在解析末尾简述依据。
6. 单个文件不得超过 10000 道题。

四、Markdown 与公式

1. `content`、选项 `text`、`standardAnswer` 字符串和 `analysis` 支持 Markdown + LaTeX。
2. 行内公式用 `$...$`，独立公式用 `$$...$$`。
3. JSON 中 LaTeX 反斜杠必须转义，例如 `\\frac{1}{2}`、`\\begin{pmatrix}`。
4. 可使用段落、列表、引用和表格；不要输出原始 HTML、JavaScript、iframe、外部脚本、远程图片或不可信链接。
5. `analysis` 要展示关键步骤并解释典型错误，不能只写“故选 A”。

五、唯一合法的导入结构

顶层格式：

{
  "schemaVersion": "global-question-bank/v1",
  "publish": false,
  "bank": {
    "id": "标准 UUID",
    "name": "文集名称",
    "description": "范围与来源说明",
    "enabled": true,
    "weight": 5
  },
  "questions": []
}

`publish` 默认使用 false，让题目进入中台待审核队列；只有我明确要求直接发布时才设为 true。

每个 `questions` 元素必须符合：

{
  "id": "标准 UUID",
  "subject": "数学一",
  "sourceType": "real_exam | mock | custom",
  "sourceName": "来源名称",
  "examYear": 2021,
  "questionNumber": "1",
  "questionType": "single_choice | multiple_choice | true_false | blank | solution",
  "presentationType": "single_choice | multiple_choice | true_false | self_assessment",
  "gradingMode": "auto | self_assessment",
  "content": "Markdown + LaTeX 题干",
  "standardAnswer": "A",
  "analysis": "Markdown + LaTeX 完整解析",
  "difficulty": 1,
  "options": [
    {"key": "A", "text": "选项内容", "correct": true, "sortOrder": 0}
  ],
  "knowledgePoints": [
    {"code": "全服知识点稳定 code", "role": "core", "sortOrder": 0}
  ]
}

字段细则：

1. 文集和题目 `id` 必须是标准 UUID，题目 UUID 在文件内唯一。修订已生成文件时必须保留原文集和原题 UUID；新增题才生成新 UUID。
2. `sourceType=real_exam` 时必须填写整数 `examYear` 和原卷 `questionNumber`；其他来源可省略这两个字段。
3. `difficulty` 是 1–5 的整数。`bank.weight` 是 0–100 的整数，通常为 5；0 表示暂不参与抽取。
4. 每题关联 1–3 个不重复的 active 知识点 code，并至少有一个 `role=core`；只允许 `core | auxiliary`。
5. `sortOrder` 从 0 起，按展示和关系优先级递增。
6. 客观题提供 2–6 个不重复选项；单选恰好一个 `correct=true`，多选至少两个，判断题固定使用 key `true` 和 `false` 且恰好一个正确。
7. 客观题 `standardAnswer` 必须与所有 `correct=true` 的选项完全一致。判断题布尔答案 `true/false` 分别对应选项 key `true/false`。
8. 自评题 `options` 必须是空数组；客观题不能使用自评展示或判题。
9. 不要输出 null、注释、尾随逗号、NaN 或未定义字段。可省略不适用的可选字段。
10. 若原题无法映射到全服知识点清单中的 1–3 个 active code，不要编造 code，也不要把该题放进文件。

六、输出前强制自检

1. 文件可由标准 `JSON.parse` 解析，顶层 `schemaVersion` 严格为 `global-question-bank/v1`。
2. 文集和题目 UUID 合法且唯一。
3. 所有知识点 code 真实存在于全服知识点清单，每题有 1–3 个关系且至少一个 core。
4. 原始题型、展示类型、判题模式组合符合规则。
5. 客观题选项、正确标记与 `standardAnswer` 完全一致；自评题无选项且有参考答案。
6. 所有公式、JSON 反斜杠、括号和 LaTeX 环境正确。
7. 答案和解析已逐题复核，不因追求题量编造知识或答案。

现在读取全部材料，生成完整文件，并只输出最终 JSON 对象。
~~~

## 导入方式

1. 登录 `/manage`，进入“批量导入”，选择或粘贴生成的 JSON。
2. 页面先显示格式、文集 UUID、题目数和发布状态，后端再进行完整事务校验。
3. 相同 UUID 重复导入会更新题目；任一题校验失败则整批回滚。
4. 自动化工具可调用 `POST /api/v1/admin/global-question-banks/import`，并通过 `X-Admin-Key` 传递服务端管理密钥。
