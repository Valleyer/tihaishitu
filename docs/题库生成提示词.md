# 《题海仕途》可导入题库生成提示词

把下面“可复制提示词”全文连同试卷 PDF、教材、讲义、答案或解析交给其他 AI。对方最终应只输出一个 UTF-8 JSON 文件。该文件可在游戏“藏书阁 → 导入 JSON / CSV”中直接导入。

> 维护约定：本文件是题库导入格式的正式生成规范。以后代码增加、删除、改名或调整任何题库、知识点、题目字段与校验规则时，必须在同一次修改中同步更新本提示词、最小输出示例和 `frontend/public/examples/题库示例.json`，并以实际导入测试确认生成文件仍可直接运行。

## 可复制提示词

~~~text
你是一名专业题库工程师、学科教研员和数据标注员。请读取我同时提供的试卷 PDF、教材、题目、答案、解析等原始资料，将其中可考查的内容改编为一份适用于自适应刷题系统的 JSON 文集。

你的最终回复只能包含一个合法 JSON 对象，不要使用 Markdown 代码围栏，不要附加解释、统计报告、道歉或任何 JSON 之外的文字。输出前必须在内部完成结构、答案、公式、知识点引用和重复题检查。

一、学习流程背景

1. 系统以“知识点”而不是固定题目数量组织考核。
2. 普通副本每轮抽取 5 个互不相同的知识点；主线考核抽取 10 个互不相同的知识点。
3. 每个知识点的第一道题决定该知识点是否得分。首题答错后，系统会继续抽取同一知识点下更简单的诊断题和训练题，直到用户答对，再进入下一个知识点。
4. 因此每个知识点必须有足量同类题，且必须包含由易到难的题目。不要只为一个知识点生成一道题。
5. 用户不设置每日题量或刷题目标。difficulty 仅供系统选择诊断题，不是让用户选择的游戏难度。

二、知识点拆分规则

1. 先阅读全部资料并建立 knowledgePoints，再生成 questions。
2. 知识点必须细到一种可以独立讲解、独立判断是否掌握的解题能力或题型步骤。
3. 合格名称示例：
   - 无条件极值的极值点判定
   - 参数方程的二阶导数计算
   - 条件概率不等式的等价变形
   - 分段函数在分界点的可导性判定
   - 中点黎曼和的取样点识别
4. 不合格名称示例：高等数学、微积分、概率论、函数、导数、第一章、综合题。它们过于宽泛。
5. 一个知识点只描述一个主要能力。如果名称中出现多个可以分别考查的并列动作，应拆分。
6. 一道题必须关联 1–3 个知识点。通常关联 1 个；确实需要连续调用多个独立能力时才关联 2–3 个。禁止超过 3 个。
7. 如果大量题都需要关联 3 个知识点，说明知识点仍然过宽或题目没有正确拆成训练步骤，应重新划分。
8. parentId 只用于表达上位目录，不参与判题。prerequisites 用于列出真正需要先掌握的细分知识点 id。
9. 每个知识点至少生成 3 道题，推荐 4–8 道：
   - 至少 1 道 difficulty=1 的概念或一步诊断题；
   - 至少 1 道 difficulty=2 的直接应用题；
   - 至少 1 道 difficulty=3 的标准题；
   - 资料允许时再生成 difficulty=4–5 的变式或综合题。
10. 同一知识点下的题必须考查同一种核心能力，但数值、叙述、选项陷阱和切入方式应变化，不能只是机械替换数字。
11. 若这份文集会用于主线考核，必须至少提供 10 个有可用题目的不同知识点；普通副本文集至少提供 5 个。原始资料确实不足时，应完整覆盖资料，不得为了凑数编造无关知识。

三、题型与改编规则

系统只接受以下三种 type：

- single_choice：单选题，通常 4 个选项，answer 是一个选项键字符串。
- multiple_choice：多选题，4–6 个选项，至少 2 个正确项，answer 是选项键数组。
- true_false：判断题，answer 是 JSON 布尔值 true 或 false；options 固定为 {"true":"正确","false":"错误"}。

原资料中的填空题、计算题、证明题和解答题必须改编成上述三种客观题之一或多道递进客观题。改编要求：

1. 保留原题真正考查的知识和推理，不要只问最终数字。
2. 可把一道大题拆成“方法选择 → 关键中间量 → 最终结论”几道题，并为每题标注准确知识点。
3. 错误选项应来自常见误区，例如漏掉定义域、符号错误、少算协方差项、混淆充分必要条件、端点未检验等。
4. 不得设置“以上都对”“以上都不对”等依赖选项位置的选项。
5. 不得在题干、标签或解析标题中泄露答案。
6. 多选题必须精确说明“下列哪些正确”或同等含义，答案数组中选项键不得重复。
7. 判断题陈述必须有唯一真值，避免“通常、可能、大概、一般而言”等无法严格判定的措辞。
8. 如果原资料答案疑似错误，先依据数学或学科知识复核。只有能确定时才修正，并在 explanation 末尾简短注明“原资料疑似笔误，已按……修正”。无法确定则不要生成该题。

四、Markdown 与数学公式

1. question、options 的值、explanation、知识点 description 和 explanation 都可以使用 Markdown + LaTeX。
2. 行内公式使用 `$...$`，独立公式使用 `$$...$$`。
3. JSON 字符串中的 LaTeX 反斜杠必须正确转义，例如 `\\frac{1}{2}`、`\\begin{pmatrix}`。
4. 可以使用 Markdown 段落、加粗、列表、引用和表格，让题面清楚易读。
5. 禁止输出原始 HTML、JavaScript、iframe、外部脚本、远程图片或不可信链接。
6. 长公式优先放在独立公式块中。矩阵、分段函数、积分上下限等必须保证 KaTeX 可以渲染。
7. explanation 必须写出关键步骤，并明确指出错误选项对应的误区；不能只写“故选 A”。

五、字段与取值规则

顶层必须是一个对象：

{
  "name": "文集名称",
  "description": "文集范围与来源简介",
  "knowledgePoints": [],
  "questions": []
}

knowledgePoints 中每项必须包含：

{
  "id": "稳定且唯一的英文小写短横线标识",
  "name": "细分知识点中文名",
  "subject": "科目名",
  "category": "学科内分类",
  "description": "一句话说明具体考查能力",
  "explanation": "Markdown + LaTeX 知识点讲解，包含定义或原理、判定步骤、常见误区、简短示例",
  "parentId": "可省略；存在时必须引用本文件内知识点 id",
  "prerequisites": ["本文件内的前置知识点 id"],
  "tags": ["便于检索的标签"]
}

questions 中每项必须包含：

{
  "id": "稳定且唯一的英文小写短横线标识",
  "subject": "必须与知识点科目一致",
  "category": "学科内分类",
  "chapter": "便于浏览的章节名称",
  "type": "single_choice | multiple_choice | true_false",
  "question": "Markdown + LaTeX 题干",
  "options": {"A":"选项", "B":"选项", "C":"选项", "D":"选项"},
  "answer": "A",
  "explanation": "Markdown + LaTeX 完整解析",
  "aliases": [],
  "keywords": ["题干同义检索词"],
  "difficulty": 1,
  "frequency": 3,
  "tags": ["题型或来源标签"],
  "knowledgePointIds": ["knowledge-point-id"],
  "enabled": true
}

字段细则：

1. id 在整个文集内唯一。只能使用英文字母、数字和短横线，不能使用空格。
2. difficulty 是 1–5 的整数：1 为概念诊断，2 为直接应用，3 为标准题，4 为复杂变式，5 为综合难题。
3. frequency 是 1–5 的整数，表示抽取重要度：核心高频考点填 4–5，普通考点填 3，低频补充填 1–2。
4. knowledgePointIds 长度必须为 1–3，且每个 id 都必须存在于 knowledgePoints。
5. aliases 与 keywords 必须是字符串数组，无内容时使用 []。
6. enabled 固定为 true。
7. 单选、多选选项键只能使用 A–F；选项数 2–6。单选 answer 是字符串，多选 answer 是字符串数组。
8. 判断题 options 必须严格为 {"true":"正确","false":"错误"}，answer 必须是不带引号的 true 或 false。
9. 不要输出 null、注释、尾随逗号、NaN 或 JSON 不支持的值。

六、生成覆盖率

1. 覆盖原资料中所有有明确答案、适合客观化的知识点。
2. 每个知识点都要有低难度诊断题，确保用户答错首题后仍有更简单的同类题可抽。
3. 同一知识点至少包含两种题面表达；条件允许时混合单选、判断、多选。
4. 控制重复：如果两题只是数字不同且解法、陷阱、结论完全一致，只保留质量更高的一题，另做真正的思路变式。
5. 原卷题可以作为 difficulty=3–5 的标准或挑战题；请额外补充 difficulty=1–2 的基础诊断题。
6. 题目总数由资料覆盖需要决定，不设置固定上限，但必须小于 10000。

七、输出前强制自检

在内部逐项检查，发现问题后先修正再输出：

1. JSON 能被标准 JSON.parse 直接解析。
2. knowledgePoints 和 questions 都非空，所有 id 唯一。
3. 每道题关联 1–3 个真实存在的知识点。
4. 每个知识点至少有 3 道题，并至少有 1 道 difficulty=1、1 道 difficulty=2。
5. parentId 与 prerequisites 只引用本文件内真实存在的知识点，且知识点不能把自身列为前置项。
6. 所有题型、选项数量、answer 类型和答案键合法。
7. 逐题重新求解，确认标准答案与解析一致。
8. 多选答案无遗漏，判断题具有唯一真值。
9. 所有 LaTeX 括号、环境与 JSON 反斜杠转义正确。
10. 不含原始 HTML、脚本或 JSON 外文本。
11. 不因追求题量而编造超出原资料或可靠学科知识的事实。

现在读取我提供的全部原始资料，建立细分知识点体系，生成完整可导入文集，并只输出最终 JSON 对象。
~~~

## 最小输出示例

以下仅展示结构，不应限制实际题量。正式生成时每个知识点仍需满足至少 3 道题和分层难度要求。

    {
      "id": "unconstrained-extremum-test",
      "name": "无条件极值的极值点判定",
      "subject": "数学一",

      "description": "利用驻点与二阶判别式判断二元函数是否取得极值。",
      "explanation": "设 $A=f_{xx}$、$B=f_{xy}$、$C=f_{yy}$，在驻点处考查 $AC-B^2$ 的符号。",
      "prerequisites": [],
      "tags": ["驻点", "二阶判别"]
    }
  ],
  "questions": [
    {
      "id": "extremum-diagnostic-001",
      "subject": "数学一",
      "category": "多元函数微分学",

      "answer": false,

      "enabled": true
    }

}

## 使用说明

1. 让其他模型把最终结果保存为 `.json`，编码使用 UTF-8。
2. 导入后先在藏书阁查看“知识点”页，确认每个知识点都有多道分层题。
3. 若模型输出了代码围栏或说明文字，要求它重新输出“仅含 JSON 对象的文件内容”。
4. 大型教材建议按科目或模块分别生成文集，避免一次上下文过大导致遗漏后半部分。
