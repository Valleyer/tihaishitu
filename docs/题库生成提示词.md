# 《万境求知》全服题目批次生成提示词

> 维护约定：本文件是正式导入格式 `global-question-batch/v4` 的唯一生成规范。代码调整字段或校验规则时，必须在同一次修改中同步更新本文和 `frontend/public/examples/题库示例.json`，并运行后端导入集成测试。

将本文件连同原始试卷 PDF、题目、教材或讲义交给其他 AI。AI 必须依据原始资料生成一份可直接导入《万境求知》管理后台的 UTF-8 JSON 文件。

## 生成任务

从输入资料中提取原题，生成全服 Question Batch。输出只负责：

1. Question；
2. Question Option；
3. Question 与全局 KnowledgePoint 的关系。

导入文件生成的是全服 Question，不是 Book。Book 不参与题目导入，也不允许出现在 JSON 中。一年真题是一份 Question Batch，不是一本书。Question 绑定全局 KnowledgePoint 后，包含这些 KnowledgePoint 的 Book 会自动获得相应的潜在训练资源。

只录入原题，不自动补充变式题，不把年份或整套试卷创建为 Book。2026、2025、2024 等年份应分别生成独立 Question Batch，并汇入同一个全局 `question_resource` 资源池。

## 输出要求

- 只输出一个合法 JSON 对象，不要输出 Markdown 代码围栏、解释或注释。
- 顶层 `schemaVersion` 必须严格为 `global-question-batch/v4`。
- 默认 `publish=false`，使新题进入 `pending_review`。
- 顶层不得包含 `bank`、`book`、`targetBookId`、`weight`、`enabled`、`chapter`。
- 所有 Question 使用标准 UUID。修订已有题目时必须继续使用原 UUID。
- **正式格式不再有 `standardAnswer` 字段**：客观题的唯一答案事实是 `options[].correct`，综合题的唯一内容事实是 `analysis`。出现 `standardAnswer` 会被判为未知字段而拒绝整批导入。
- Markdown 与 LaTeX 保留在 `content`、`analysis` 或选项文本中；不要生成 HTML。
- JSON 中 LaTeX 的反斜杠必须正确转义，例如 `\\frac{1}{x}`。

## 顶层结构

```json
{
  "schemaVersion": "global-question-batch/v4",
  "publish": false,
  "batch": {
    "subject": "数学一",
    "sourceType": "real_exam",
    "sourceName": "全国硕士研究生招生考试数学一",
    "examYear": 2025
  },
  "questions": []
}
```

### batch

- `subject`：必填，作为题目来源与检索元数据；V4 不再要求它与所有引用 KnowledgePoint 的 legacy `subject_name` 一致。
- `sourceType`：只能是 `real_exam`、`mock`、`custom`。
- `sourceName`：必填，同一文件共享同一来源名称。
- `examYear`：`real_exam` 必填整数，其他来源可省略。

同一文件中的题目不得重复保存 batch 字段。

## Question 结构

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "questionNumber": "1",
  "questionType": "single_choice",
  "presentationType": "single_choice",
  "gradingMode": "auto",
  "content": "设 $f(x)$ 满足……",
  "analysis": "由极限定义可知，逐项判断后只有 A 成立。",
  "difficulty": 3,
  "options": [
    { "key": "A", "text": "$0$", "correct": true, "sortOrder": 0 },
    { "key": "B", "text": "$1$", "correct": false, "sortOrder": 1 }
  ],
  "knowledgePoints": [
    { "code": "M1-H01-001", "role": "core", "sortOrder": 0 }
  ]
}
```

- `id`：标准 UUID，批次内唯一。
- `questionNumber`：`real_exam` 必填，且同一批次内唯一；其他来源可选。原题有小问时保留在同一个 Question 中。
- `content`、`analysis`：必填，且不得为空白。题干与解析使用 Markdown + LaTeX。
- 客观题的答案只由 `options[].correct` 表达，不写 `standardAnswer`。
- 综合题不写 `standardAnswer`；`analysis` 是唯一内容事实，必须包含答案、过程与解析。
- `difficulty`：整数 1～5。
- `options`：始终提供数组；自评题使用空数组。
- `knowledgePoints`：始终提供数组，数量 1～3，code 不得重复，至少一个 `core`。

## 正式题型与原填空题改编规则

万境求知只接受以下四种固定字段组合：

| 正式题型 | questionType | presentationType | gradingMode |
| --- | --- | --- | --- |
| 单选 | `single_choice` | `single_choice` | `auto` |
| 多选 | `multiple_choice` | `multiple_choice` | `auto` |
| 判断 | `true_false` | `true_false` | `auto` |
| 综合题 | `solution` | `self_assessment` | `self_assessment` |

原卷填空题禁止输出 `blank`。保持原题题干、题号、来源身份和 Question UUID，
在生成阶段补充可信干扰项后优先转换为单选题；只有数学语义确有多个不同且均应选择的答案时才转换为多选题。
不得把同一正确答案的等价表达当作多个正确选项。系统不会代替题目生成 AI 猜测干扰项。

综合题的 `analysis` 必须是完整的 Markdown 字符串，包含答案、推导过程与解析，供用户作答后对照自评。
综合题不再有独立的 `standardAnswer`；如果历史资料里答案与解析分开，请在生成阶段合并进同一个 `analysis`（可用
`## 参考答案` / `## 解析` 小标题组织，但它们属于同一字段的内容）。

## 客观题选项和答案

- 客观题必须有 2～6 个选项，`key` 唯一且选项文本非空。
- 单选题恰好一个 `correct=true`。
- 多选题至少两个 `correct=true`。
- 判断题恰好两个选项和一个正确项，key 必须使用 `true`、`false`。
- 客观题的答案事实只有 `options[].correct`，**不要输出 `standardAnswer`**。
- 自评题不得包含选项，且 `analysis` 非空。

## KnowledgePoint 标注

每题只能绑定 1～3 个足够细的全局知识点：

- code 必须来自提供给你的正式 KnowledgePoint 清单；禁止自造 code。
- KnowledgePoint 必须处于 active 状态；V4 允许一题关联跨 legacy subject 的知识点。
- `core` 表示这道题主要训练、主要考查的知识点；至少一个。
- `auxiliary` 表示解题需要但并非主要训练目标的知识点。
- 同一题不得重复绑定同一 code。
- 如果一道题需要大量标签，应重新分析并只保留真正决定解法的 1～3 个细分知识点。

## 真题身份和 UUID

系统把以下组合作为第一版真题自然身份：

```text
subject + sourceType(real_exam) + examYear + questionNumber
```

同一真题身份若数据库中已存在，必须复用原 Question UUID。使用不同 UUID 会被拒绝，以防同一道真题重复入库。

## v3 / v2 历史兼容输入

管理后台导入 UI 与 `/manage/imports/questions` 仍然接受 `global-question-batch/v3`
与 `v2`，但只作为**兼容输入**，新生成的内容一律使用 v4：

```text
v3 / v2 客观题：standardAnswer 只做与 options.correct 的一致性校验，最终不持久化
v3 / v2 综合题：standardAnswer + analysis 合并进 analysis_markdown
两种情况下 Formal Parent 的 standard_answer_json 都写为 NULL
```

v3 的 `questionNumber` 一致性规则与真题自然身份规则与 v4 相同。不要为了使用兼容能力而继续产出 v3。

## 输出前自检

1. 顶层格式是否严格为 `global-question-batch/v4`。
2. 是否完全没有 Book、bank、chapter 或文集字段。
3. 是否完全没有 `standardAnswer` 字段。
4. batch 科目、来源、年份是否统一且准确。
5. 真题 questionNumber 是否填写且批次内唯一。
6. 是否只录入原题，没有生成变式题。
7. 是否只使用四种正式题型；原填空题是否保留 UUID 并已转换为带可信干扰项的单选或多选题。
8. 客观题的 `options[].correct` 是否与题面答案一致，且数量约束（2～6 个选项、单选 1 个正确、多选至少 2 个正确、判断 true/false 各一）成立。
9. 综合题是否只有一份包含答案与过程非空的 `analysis`。
10. 每题是否绑定 1～3 个 active 正式 KnowledgePoint，且至少一个 core。
11. difficulty 是否为 1～5。
12. UUID 是否稳定；已有题目是否复用原 UUID。

满足全部条件后，只输出最终 JSON。
